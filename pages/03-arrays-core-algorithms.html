Basic Array Operations

Q1. Reverse the elements in a list (array).

Problem statement: Given an array of integers, reverse the order of its elements IN PLACE (without allocating a new array). Example: reverseArrayInPlace({1, 2, 3, 4, 5}) should transform the array into {5, 4, 3, 2, 1}.

public class ArrayReverser {
 
    public static void reverseArrayInPlace(int[] inputArray) {
        int leftIndex = 0;
        int rightIndex = inputArray.length - 1;
 
        while (leftIndex < rightIndex) {
            int temporaryValue = inputArray[leftIndex];
            inputArray[leftIndex] = inputArray[rightIndex];
            inputArray[rightIndex] = temporaryValue;
            leftIndex++;
            rightIndex--;
        }
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {1, 2, 3, 4, 5};
        reverseArrayInPlace(numberArray);
        System.out.println(java.util.Arrays.toString(numberArray)); // [5, 4, 3, 2, 1]
    }
}

Complexity: O(n) time, O(1) extra space, since the array is reversed in place with only two pointers.

Q2. Rotate an array by a value of k.
LeetCode: Rotate Array ↗

Problem statement: Given an array and an integer rotationAmount, rotate the array to the RIGHT by rotationAmount positions. Example: rotateArrayRight({1, 2, 3, 4, 5, 6, 7}, 3) should produce {5, 6, 7, 1, 2, 3, 4}.

Approach: the elegant "triple reversal" trick performs the rotation in place using O(1) extra space: reverse the ENTIRE array, then reverse the first rotationAmount elements, then reverse the remaining elements.

public class ArrayRotator {
 
    // Reverses the portion of numberArray between startIndex and endIndex, inclusive
    private static void reverseArrayRange(int[] numberArray, int startIndex, int endIndex) {
        while (startIndex < endIndex) {
            int temporaryValue = numberArray[startIndex];
            numberArray[startIndex] = numberArray[endIndex];
            numberArray[endIndex] = temporaryValue;
            startIndex++;
            endIndex--;
        }
    }
 
    public static void rotateArrayRight(int[] numberArray, int rotationAmount) {
        int arrayLength = numberArray.length;
        // normalize in case rotationAmount is larger than the array length
        int normalizedRotation = rotationAmount % arrayLength;
        if (normalizedRotation < 0) {
            normalizedRotation += arrayLength;
        }
 
        // Step 1: reverse the whole array
        reverseArrayRange(numberArray, 0, arrayLength - 1);
        // Step 2: reverse the first "normalizedRotation" elements (now at the front)
        reverseArrayRange(numberArray, 0, normalizedRotation - 1);
        // Step 3: reverse the remaining elements
        reverseArrayRange(numberArray, normalizedRotation, arrayLength - 1);
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {1, 2, 3, 4, 5, 6, 7};
        rotateArrayRight(numberArray, 3);
        System.out.println(java.util.Arrays.toString(numberArray)); // [5, 6, 7, 1, 2, 3, 4]
    }
}
Note: Walking through why the triple-reversal trick works: reversing the WHOLE array puts every element in reverse order, but this also has the side effect of putting the LAST rotationAmount elements at the FRONT (though themselves individually reversed) and the rest at the back (also individually reversed). Reversing each of those two segments separately un-reverses each segment internally, leaving the overall array correctly rotated.

Complexity: O(n) time, O(1) extra space.

Q3. Merge two sorted arrays (and, separately, merge two arbitrary arrays of numbers).
LeetCode: Merge Sorted Array ↗

Problem statement: Given two arrays, each already sorted in ascending order, merge them into a single, combined sorted array. Example: mergeSortedArrays({1, 3, 5}, {2, 4, 6}) should return {1, 2, 3, 4, 5, 6}.

public class SortedArrayMerger {
 
    public static int[] mergeSortedArrays(int[] firstArray, int[] secondArray) {
        int[] mergedResult = new int[firstArray.length + secondArray.length];
        int firstPointer = 0;
        int secondPointer = 0;
        int mergedPointer = 0;
 
        // walk both arrays together, always taking the smaller current element
        while (firstPointer < firstArray.length && secondPointer < secondArray.length) {
            if (firstArray[firstPointer] <= secondArray[secondPointer]) {
                mergedResult[mergedPointer++] = firstArray[firstPointer++];
            } else {
                mergedResult[mergedPointer++] = secondArray[secondPointer++];
            }
        }
        // copy any remaining elements from whichever array still has some left
        while (firstPointer < firstArray.length) {
            mergedResult[mergedPointer++] = firstArray[firstPointer++];
        }
        while (secondPointer < secondArray.length) {
            mergedResult[mergedPointer++] = secondArray[secondPointer++];
        }
        return mergedResult;
    }
 
    public static void main(String[] arguments) {
        int[] mergedArray = mergeSortedArrays(new int[]{1, 3, 5}, new int[]{2, 4, 6});
        System.out.println(java.util.Arrays.toString(mergedArray)); // [1, 2, 3, 4, 5, 6]
    }
}

If the two input arrays are NOT sorted, simply concatenate them and sort the combined result (O((n+m) log(n+m)) time), since there is no useful order to exploit.

Complexity: O(n + m) time for the sorted-array-merge version, where n and m are the two array lengths. O(n + m) extra space for the result array.

Q4. Find the average of an array.

Problem statement: Given an array of numbers, compute the arithmetic average (mean) of its elements.

public class ArrayAverageCalculator {
 
    public static double calculateAverage(int[] numberArray) {
        if (numberArray.length == 0) {
            throw new IllegalArgumentException("Cannot compute the average of an empty array");
        }
        long totalSum = 0;
        for (int currentValue : numberArray) {
            totalSum += currentValue;
        }
        return (double) totalSum / numberArray.length;
    }
 
    public static void main(String[] arguments) {
        int[] scoresArray = {85, 90, 78, 92, 88};
        System.out.println(calculateAverage(scoresArray)); // 86.6
    }
}

Complexity: O(n) time, O(1) extra space.

Finding Specific Elements

Q5. Find the duplicate integer in an array.
LeetCode: Find The Duplicate Number ↗

Problem statement: Given an array of n+1 integers where every integer is between 1 and n (inclusive), and exactly one value is duplicated (appearing more than once), find that duplicate value. Example: findDuplicateInteger({1, 3, 4, 2, 2}) should return 2.

import java.util.HashSet;
import java.util.Set;
 
public class DuplicateIntegerFinder {
 
    // Approach using a HashSet: track every value seen so far; the first
    // value seen AGAIN is the duplicate
    public static int findDuplicateInteger(int[] numberArray) {
        Set<Integer> seenValues = new HashSet<>();
        for (int currentValue : numberArray) {
            if (!seenValues.add(currentValue)) {
                // add() returns false if the value was ALREADY present in the set
                return currentValue;
            }
        }
        throw new IllegalArgumentException("No duplicate value found in the array");
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {1, 3, 4, 2, 2};
        System.out.println(findDuplicateInteger(numberArray)); // 2
    }
}
Note: A more advanced, O(1)-extra-space solution exists using Floyd's Cycle Detection (treating the array as a linked structure where each value points to the index it equals, and finding the cycle that the duplicate necessarily creates) -- this is a common, more difficult follow-up question if the interviewer specifically prohibits extra space.

Complexity: O(n) time, O(n) extra space for the HashSet-based solution.

Q6. Find the second smallest number in an array. (Asked multiple times in the original list.)

Problem statement: Given an unsorted array of integers, find the SECOND smallest distinct value. Example: findSecondSmallest({5, 2, 8, 2, 9, 1}) should return 2 (the smallest is 1, and the second smallest distinct value is 2).

public class SecondSmallestFinder {
 
    public static int findSecondSmallest(int[] numberArray) {
        if (numberArray.length < 2) {
            throw new IllegalArgumentException("Array must contain at least two distinct values");
        }
 
        int smallestValue = Integer.MAX_VALUE;
        int secondSmallestValue = Integer.MAX_VALUE;
 
        for (int currentValue : numberArray) {
            if (currentValue < smallestValue) {
                // current value becomes the new smallest;
                // the PREVIOUS smallest becomes the new second-smallest
                secondSmallestValue = smallestValue;
                smallestValue = currentValue;
            } else if (currentValue < secondSmallestValue && currentValue != smallestValue) {
                // strictly between smallest and secondSmallest, and not a
                // duplicate of the smallest value
                secondSmallestValue = currentValue;
            }
        }
 
        if (secondSmallestValue == Integer.MAX_VALUE) {
            throw new IllegalArgumentException("Array does not contain two distinct values");
        }
        return secondSmallestValue;
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {5, 2, 8, 2, 9, 1};
        System.out.println(findSecondSmallest(numberArray)); // 2
    }
}

Complexity: O(n) time (a single pass), O(1) extra space -- considerably better than sorting the array first, which would cost O(n log n).

Q7. Given a sorted, rotated array, find the minimum element. Must run in O(log n) time.
LeetCode: Find Minimum In Rotated Sorted Array ↗

Problem statement: An array was originally sorted in increasing order, but has since been rotated at some unknown pivot point (e.g. {4, 5, 6, 1, 2, 3} was originally {1, 2, 3, 4, 5, 6}, rotated). Find the minimum element, in O(log n) time (ruling out a simple linear scan).

Approach: use a modified binary search. At each step, compare the middle element to the rightmost element -- this comparison always reveals which half of the current range contains the "rotation point" (and therefore the minimum).

public class RotatedArrayMinimumFinder {
 
    public static int findMinimumInRotatedArray(int[] rotatedArray) {
        int leftIndex = 0;
        int rightIndex = rotatedArray.length - 1;
 
        while (leftIndex < rightIndex) {
            int middleIndex = leftIndex + (rightIndex - leftIndex) / 2;
 
            if (rotatedArray[middleIndex] > rotatedArray[rightIndex]) {
                // the minimum must be somewhere to the RIGHT of middleIndex,
                // since the right half is "broken" (contains the rotation point)
                leftIndex = middleIndex + 1;
            } else {
                // the right half, from middleIndex onward, is properly sorted,
                // so the minimum is at middleIndex OR somewhere to its left
                rightIndex = middleIndex;
            }
        }
        return rotatedArray[leftIndex]; // leftIndex and rightIndex converge on the minimum
    }
 
    public static void main(String[] arguments) {
        System.out.println(findMinimumInRotatedArray(new int[]{4, 5, 6, 1, 2, 3})); // 1
        System.out.println(findMinimumInRotatedArray(new int[]{6, 1, 2, 3, 4, 5})); // 1
    }
}

Complexity: O(log n) time, since the search range is halved at every step (a modified binary search). O(1) extra space.

Subarray & Sum Problems

Q8. Find the maximum sum subarray.
LeetCode: Maximum Subarray ↗

Problem statement: Given an array of integers (which may include negative numbers), find the contiguous subarray with the LARGEST sum, and return that sum. Example: findMaximumSubarraySum({-2, 1, -3, 4, -1, 2, 1, -5, 4}) should return 6 (the subarray {4, -1, 2, 1}).

Approach: Kadane's Algorithm -- at each position, decide whether to extend the previous subarray or start a brand new one, keeping whichever choice yields a larger sum.

public class MaximumSubarraySumFinder {
 
    public static int findMaximumSubarraySum(int[] numberArray) {
        int bestSumEndingHere = numberArray[0];
        int bestSumOverall = numberArray[0];
 
        for (int currentIndex = 1; currentIndex < numberArray.length; currentIndex++) {
            // either extend the previous subarray, or start fresh at this element
            bestSumEndingHere = Math.max(numberArray[currentIndex],
                bestSumEndingHere + numberArray[currentIndex]);
            bestSumOverall = Math.max(bestSumOverall, bestSumEndingHere);
        }
        return bestSumOverall;
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {-2, 1, -3, 4, -1, 2, 1, -5, 4};
        System.out.println(findMaximumSubarraySum(numberArray)); // 6
    }
}

Complexity: O(n) time (a single pass), O(1) extra space.

Q9. Find subarrays whose sum is greater than or equal to a given number.
LeetCode: Minimum Size Subarray Sum ↗

Problem statement: Given an array of positive integers and a target sum, find the LENGTH of the SHORTEST contiguous subarray whose sum is greater than or equal to the target. Example: findShortestSubarrayAtLeastSum({2, 3, 1, 2, 4, 3}, 7) should return 2 (the subarray {4, 3} sums to 7, and is the shortest such subarray).

Approach: the variable-size sliding window pattern -- expand the window to the right, and whenever its sum meets or exceeds the target, shrink it from the left as much as possible while still satisfying the target, tracking the shortest valid window seen.

public class MinimumSubarrayLengthFinder {
 
    public static int findShortestSubarrayAtLeastSum(int[] numberArray, int targetSum) {
        int leftBoundary = 0;
        int currentWindowSum = 0;
        int shortestLengthFound = Integer.MAX_VALUE;
 
        for (int rightBoundary = 0; rightBoundary < numberArray.length; rightBoundary++) {
            currentWindowSum += numberArray[rightBoundary]; // expand the window
 
            // shrink the window from the left while it still meets the target
            while (currentWindowSum >= targetSum) {
                int currentWindowLength = rightBoundary - leftBoundary + 1;
                shortestLengthFound = Math.min(shortestLengthFound, currentWindowLength);
 
                currentWindowSum -= numberArray[leftBoundary];
                leftBoundary++;
            }
        }
        return shortestLengthFound == Integer.MAX_VALUE ? 0 : shortestLengthFound;
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {2, 3, 1, 2, 4, 3};
        System.out.println(findShortestSubarrayAtLeastSum(numberArray, 7)); // 2
    }
}

Complexity: O(n) time -- although there is a nested while loop, each element is added to the window exactly once and removed at most once across the whole run, so the total work remains linear. O(1) extra space.

Q10. Find the minimum sum of integers equal to or less than a given number.

Problem statement: Given an array of positive integers and a target upper bound, find the MAXIMUM possible sum of a subset of the array's elements that does not EXCEED the target. (Interpreting the original question's intent: among all subsets whose sum is at most the target, find the one closest to -- i.e. the largest sum not exceeding -- the target.) Example: findClosestSumNotExceeding({3, 7, 2, 9}, 12) should return 12 (using 3 + 9, or checking other subsets, whichever combination gets closest to but not over 12).

Approach: this is a variation of the classic 0/1 Knapsack problem -- decide, for each element, whether to include it or not, to maximize the resulting sum without exceeding the target.

public class ClosestSubsetSumFinder {
 
    public static int findClosestSumNotExceeding(int[] numberArray, int targetUpperBound) {
        // achievableSums[amount] = true if some subset of the array sums to EXACTLY "amount"
        boolean[] achievableSums = new boolean[targetUpperBound + 1];
        achievableSums[0] = true; // a sum of 0 is always achievable (the empty subset)
 
        for (int currentValue : numberArray) {
            // iterate the achievable-sums table BACKWARD to avoid reusing the
            // same array element more than once within a single subset
            for (int currentAmount = targetUpperBound; currentAmount >= currentValue; currentAmount--) {
                if (achievableSums[currentAmount - currentValue]) {
                    achievableSums[currentAmount] = true;
                }
            }
        }
 
        // search downward from the target for the largest achievable sum
        for (int currentAmount = targetUpperBound; currentAmount >= 0; currentAmount--) {
            if (achievableSums[currentAmount]) {
                return currentAmount;
            }
        }
        return 0;
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {3, 7, 2, 9};
        System.out.println(findClosestSumNotExceeding(numberArray, 12)); // 12 (3 + 9)
    }
}

Complexity: O(n x targetUpperBound) time and space, a classic 0/1 Knapsack-style dynamic programming solution.

Two/Three/Four Sum & Target Pair Problems

Q11. 2 Sum, 3 Sum, and 4 Sum problems.
LeetCode: Two Sum ↗ 3Sum ↗ 4Sum ↗

Problem statement: 2Sum: given an array and a target, find two numbers that add up to the target. 3Sum: find three numbers that add up to a target (commonly zero). 4Sum: find four numbers that add up to a target. All three are variations on the same underlying two-pointer technique.

2Sum (using a HashMap for unsorted input, O(n) time)

import java.util.HashMap;
import java.util.Map;
 
public class TwoSumFinder {
 
    public static int[] findTwoNumbersSummingToTarget(int[] numberArray, int targetSum) {
        Map<Integer, Integer> valueToIndexMap = new HashMap<>();
 
        for (int currentIndex = 0; currentIndex < numberArray.length; currentIndex++) {
            int requiredComplement = targetSum - numberArray[currentIndex];
            if (valueToIndexMap.containsKey(requiredComplement)) {
                return new int[]{valueToIndexMap.get(requiredComplement), currentIndex};
            }
            valueToIndexMap.put(numberArray[currentIndex], currentIndex);
        }
        return new int[]{-1, -1}; // no valid pair found
    }
 
    public static void main(String[] arguments) {
        int[] resultIndices = findTwoNumbersSummingToTarget(new int[]{2, 7, 11, 15}, 9);
        System.out.println(java.util.Arrays.toString(resultIndices)); // [0, 1]
    }
}

3Sum (sort first, then two-pointer for each fixed element)

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
 
public class ThreeSumFinder {
 
    public static List<List<Integer>> findAllTripletsSummingToZero(int[] numberArray) {
        Arrays.sort(numberArray); // sorting enables the two-pointer scan below
        List<List<Integer>> resultTriplets = new ArrayList<>();
 
        for (int fixedIndex = 0; fixedIndex < numberArray.length - 2; fixedIndex++) {
            if (fixedIndex > 0 && numberArray[fixedIndex] == numberArray[fixedIndex - 1]) {
                continue; // skip duplicate "fixed" values to avoid duplicate triplets
            }
 
            int leftIndex = fixedIndex + 1;
            int rightIndex = numberArray.length - 1;
 
            while (leftIndex < rightIndex) {
                int tripletSum = numberArray[fixedIndex] + numberArray[leftIndex] + numberArray[rightIndex];
 
                if (tripletSum == 0) {
                    resultTriplets.add(Arrays.asList(
                        numberArray[fixedIndex], numberArray[leftIndex], numberArray[rightIndex]));
                    while (leftIndex < rightIndex && numberArray[leftIndex] == numberArray[leftIndex + 1]) leftIndex++;
                    while (leftIndex < rightIndex && numberArray[rightIndex] == numberArray[rightIndex - 1]) rightIndex--;
                    leftIndex++;
                    rightIndex--;
                } else if (tripletSum < 0) {
                    leftIndex++;
                } else {
                    rightIndex--;
                }
            }
        }
        return resultTriplets;
    }
 
    public static void main(String[] arguments) {
        System.out.println(findAllTripletsSummingToZero(new int[]{-1, 0, 1, 2, -1, -4}));
        // [[-1, -1, 2], [-1, 0, 1]]
    }
}

4Sum (fix two elements, two-pointer the rest)

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
 
public class FourSumFinder {
 
    public static List<List<Integer>> findAllQuadrupletsSummingToTarget(int[] numberArray, int targetSum) {
        Arrays.sort(numberArray);
        List<List<Integer>> resultQuadruplets = new ArrayList<>();
        int arrayLength = numberArray.length;
 
        for (int firstIndex = 0; firstIndex < arrayLength - 3; firstIndex++) {
            if (firstIndex > 0 && numberArray[firstIndex] == numberArray[firstIndex - 1]) continue;
 
            for (int secondIndex = firstIndex + 1; secondIndex < arrayLength - 2; secondIndex++) {
                if (secondIndex > firstIndex + 1 && numberArray[secondIndex] == numberArray[secondIndex - 1]) continue;
 
                int leftIndex = secondIndex + 1;
                int rightIndex = arrayLength - 1;
 
                while (leftIndex < rightIndex) {
                    long quadrupletSum = (long) numberArray[firstIndex] + numberArray[secondIndex]
                        + numberArray[leftIndex] + numberArray[rightIndex];
 
                    if (quadrupletSum == targetSum) {
                        resultQuadruplets.add(Arrays.asList(numberArray[firstIndex], numberArray[secondIndex],
                            numberArray[leftIndex], numberArray[rightIndex]));
                        while (leftIndex < rightIndex && numberArray[leftIndex] == numberArray[leftIndex + 1]) leftIndex++;
                        while (leftIndex < rightIndex && numberArray[rightIndex] == numberArray[rightIndex - 1]) rightIndex--;
                        leftIndex++;
                        rightIndex--;
                    } else if (quadrupletSum < targetSum) {
                        leftIndex++;
                    } else {
                        rightIndex--;
                    }
                }
            }
        }
        return resultQuadruplets;
    }
 
    public static void main(String[] arguments) {
        System.out.println(findAllQuadrupletsSummingToTarget(new int[]{1, 0, -1, 0, -2, 2}, 0));
        // [[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]
    }
}

Complexity: 2Sum is O(n) time using a HashMap. 3Sum is O(n^2) time (an O(n) outer loop combined with an O(n) two-pointer scan for each fixed element). 4Sum is O(n^3) time (two nested fixed loops combined with an O(n) two-pointer scan). This pattern generalizes: kSum generally costs O(n^(k-1)) time using this fix-and-two-pointer technique.

Q12. Given two arrays and a target sum, check whether a pair (one element from each array) can reach the target sum.

Problem statement: Given two arrays and a target sum, determine whether there EXISTS a pair of numbers -- one taken from EACH array -- that adds up to exactly the target. Example: canFormTargetPair({1, 2, 3}, {4, 5, 6}, 9) should return true (3 + 6 = 9).

import java.util.HashSet;
import java.util.Set;
 
public class CrossArrayPairFinder {
 
    public static boolean canFormTargetPair(int[] firstArray, int[] secondArray, int targetSum) {
        Set<Integer> firstArrayValues = new HashSet<>();
        for (int currentValue : firstArray) {
            firstArrayValues.add(currentValue);
        }
 
        for (int currentValue : secondArray) {
            int requiredComplement = targetSum - currentValue;
            if (firstArrayValues.contains(requiredComplement)) {
                return true;
            }
        }
        return false;
    }
 
    public static void main(String[] arguments) {
        System.out.println(canFormTargetPair(new int[]{1, 2, 3}, new int[]{4, 5, 6}, 9)); // true
        System.out.println(canFormTargetPair(new int[]{1, 2, 3}, new int[]{4, 5, 6}, 20)); // false
    }
}

Complexity: O(n + m) time, where n and m are the two array lengths. O(n) extra space for the HashSet.

Q13. Return the total number of possible pairs that add up to a target.

Problem statement: Given an array of integers and a target sum, count how many DISTINCT PAIRS of elements (by index) add up to the target. Example: countPairsSummingToTarget({1, 5, 7, -1, 5}, 6) should return 3 (pairs: (1,5) at indices 0,1; (7,-1) at indices 2,3; (1,5) at indices 0,4).

import java.util.HashMap;
import java.util.Map;
 
public class TargetPairCounter {
 
    public static int countPairsSummingToTarget(int[] numberArray, int targetSum) {
        Map<Integer, Integer> valueFrequencyMap = new HashMap<>();
        int pairCount = 0;
 
        for (int currentValue : numberArray) {
            int requiredComplement = targetSum - currentValue;
 
            // add however many times the complement has already been seen --
            // each prior occurrence forms a valid pair with the current element
            pairCount += valueFrequencyMap.getOrDefault(requiredComplement, 0);
 
            valueFrequencyMap.merge(currentValue, 1, Integer::sum);
        }
        return pairCount;
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {1, 5, 7, -1, 5};
        System.out.println(countPairsSummingToTarget(numberArray, 6)); // 3
    }
}

Complexity: O(n) time, O(n) extra space for the frequency map.

Trapping Rain Water & Structural Array Problems

Q14. Trapping rain water. (Asked multiple times in the original list.)
LeetCode: Trapping Rain Water ↗

Problem statement: Given an array of non-negative integers representing an elevation map (each value is a bar's height, with width 1), compute how much rainwater the terrain can TRAP between the bars after it rains. Example: calculateTrappedWater({0,1,0,2,1,0,1,3,2,1,2,1}) should return 6.

Approach: for each position, the amount of water it can hold is determined by the SHORTER of the tallest bar to its left and the tallest bar to its right (water can't rise higher than the shorter of the two "walls" containing it), minus the height of the bar at that position itself (if positive).

public class TrappedRainWaterCalculator {
 
    public static int calculateTrappedWater(int[] elevationHeights) {
        if (elevationHeights.length == 0) {
            return 0;
        }
 
        int leftIndex = 0;
        int rightIndex = elevationHeights.length - 1;
        int tallestFromLeft = 0;
        int tallestFromRight = 0;
        int totalTrappedWater = 0;
 
        // two-pointer approach: always process the side with the SHORTER
        // current wall, since that side's trapped-water amount is already
        // fully determined by the taller wall on the OTHER side
        while (leftIndex < rightIndex) {
            if (elevationHeights[leftIndex] < elevationHeights[rightIndex]) {
                tallestFromLeft = Math.max(tallestFromLeft, elevationHeights[leftIndex]);
                totalTrappedWater += tallestFromLeft - elevationHeights[leftIndex];
                leftIndex++;
            } else {
                tallestFromRight = Math.max(tallestFromRight, elevationHeights[rightIndex]);
                totalTrappedWater += tallestFromRight - elevationHeights[rightIndex];
                rightIndex--;
            }
        }
        return totalTrappedWater;
    }
 
    public static void main(String[] arguments) {
        int[] elevationHeights = {0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1};
        System.out.println(calculateTrappedWater(elevationHeights)); // 6
    }
}

Complexity: O(n) time (a single pass with two pointers), O(1) extra space -- an improvement over the more intuitive brute-force approach of precomputing full left-max and right-max arrays (which uses O(n) extra space).

Q15. Given an array of integers, can you rearrange it into a series like a1 <= a2 >= a3 <= a4 ... (a "wiggle" or "zigzag" pattern)?
LeetCode: Wiggle Sort ↗

Problem statement: Given an array, rearrange its elements so that they alternate between being less-than-or-equal-to and greater-than-or-equal-to their neighbors, forming a zigzag pattern. Example: rearrangeIntoZigzagPattern({3, 5, 2, 1, 6, 4}) should produce an array such as {3, 5, 1, 6, 2, 4}, where element[0] <= element[1] >= element[2] <= element[3] >= element[4] <= element[5].

public class ZigzagArrangementBuilder {
 
    public static void rearrangeIntoZigzagPattern(int[] numberArray) {
        for (int currentIndex = 0; currentIndex < numberArray.length - 1; currentIndex++) {
            // determine whether THIS position should be a "peak" (>=) or
            // a "valley" (<=) relative to the NEXT element
            boolean shouldBeGreaterOrEqual = (currentIndex % 2 == 0);
 
            boolean currentlySatisfiesCondition = shouldBeGreaterOrEqual
                ? numberArray[currentIndex] >= numberArray[currentIndex + 1]
                : numberArray[currentIndex] <= numberArray[currentIndex + 1];
 
            if (!currentlySatisfiesCondition) {
                // swap this element with the next one to satisfy the required
                // relationship at this position
                int temporaryValue = numberArray[currentIndex];
                numberArray[currentIndex] = numberArray[currentIndex + 1];
                numberArray[currentIndex + 1] = temporaryValue;
            }
        }
    }
 
    public static void main(String[] arguments) {
        int[] numberArray = {3, 5, 2, 1, 6, 4};
        rearrangeIntoZigzagPattern(numberArray);
        System.out.println(java.util.Arrays.toString(numberArray));
        // A valid zigzag arrangement, e.g. [3, 5, 1, 6, 2, 4]
    }
}

Complexity: O(n) time (a single greedy pass, swapping adjacent elements as needed), O(1) extra space (the rearrangement happens in place).
