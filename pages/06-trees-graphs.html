Tree Traversal

Q1. Binary tree traversal. (Asked twice in the original list, once generically and once specifically for binary trees.)
LeetCode: Related: Binary Tree Inorder Traversal ↗

Problem statement: Given the root of a binary tree, visit every node using each of the standard traversal orders: pre-order (node, then left, then right), in-order (left, then node, then right), post-order (left, then right, then node), and level-order (breadth-first, level by level).

import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;
 
public class BinaryTreeTraverser {
 
    // Pre-order: process the node BEFORE its children
    public static void traversePreOrder(TreeNode currentNode, List<Integer> resultList) {
        if (currentNode == null) {
            return;
        }
        resultList.add(currentNode.nodeValue);          // visit the node first
        traversePreOrder(currentNode.leftChild, resultList);
        traversePreOrder(currentNode.rightChild, resultList);
    }
 
    // In-order: process the node BETWEEN its children (produces sorted
    // order for a valid Binary Search Tree)
    public static void traverseInOrder(TreeNode currentNode, List<Integer> resultList) {
        if (currentNode == null) {
            return;
        }
        traverseInOrder(currentNode.leftChild, resultList);
        resultList.add(currentNode.nodeValue);            // visit the node between children
        traverseInOrder(currentNode.rightChild, resultList);
    }
 
    // Post-order: process the node AFTER both children
    public static void traversePostOrder(TreeNode currentNode, List<Integer> resultList) {
        if (currentNode == null) {
            return;
        }
        traversePostOrder(currentNode.leftChild, resultList);
        traversePostOrder(currentNode.rightChild, resultList);
        resultList.add(currentNode.nodeValue);             // visit the node last
    }
 
    // Level-order (breadth-first): visits all nodes at depth 0, then depth 1, etc.
    public static List<Integer> traverseLevelOrder(TreeNode rootNode) {
        List<Integer> resultList = new ArrayList<>();
        if (rootNode == null) {
            return resultList;
        }
        Queue<TreeNode> nodesToVisit = new LinkedList<>();
        nodesToVisit.offer(rootNode);
 
        while (!nodesToVisit.isEmpty()) {
            TreeNode currentNode = nodesToVisit.poll();
            resultList.add(currentNode.nodeValue);
            if (currentNode.leftChild != null) nodesToVisit.offer(currentNode.leftChild);
            if (currentNode.rightChild != null) nodesToVisit.offer(currentNode.rightChild);
        }
        return resultList;
    }
 
    public static void main(String[] arguments) {
        TreeNode rootNode = new TreeNode(4);
        rootNode.leftChild = new TreeNode(2);
        rootNode.rightChild = new TreeNode(6);
        rootNode.leftChild.leftChild = new TreeNode(1);
        rootNode.leftChild.rightChild = new TreeNode(3);
 
        List<Integer> preOrderResult = new ArrayList<>();
        traversePreOrder(rootNode, preOrderResult);
        System.out.println("Pre-order: " + preOrderResult);   // [4, 2, 1, 3, 6]
 
        List<Integer> inOrderResult = new ArrayList<>();
        traverseInOrder(rootNode, inOrderResult);
        System.out.println("In-order: " + inOrderResult);     // [1, 2, 3, 4, 6]
 
        System.out.println("Level-order: " + traverseLevelOrder(rootNode)); // [4, 2, 6, 1, 3]
    }
}

Complexity: O(n) time for every traversal style, since each visits every node exactly once. O(h) extra space for the recursive traversals (where h is the tree's height, due to call-stack depth), and O(w) extra space for level-order traversal (where w is the tree's maximum width, due to the queue).

Q2. Print a binary tree in spiral order.
LeetCode: Related: Binary Tree Zigzag Level Order Traversal ↗

Problem statement: Given the root of a binary tree, print its nodes in SPIRAL (zigzag) order: the first level left-to-right, the second level right-to-left, the third level left-to-right again, and so on, alternating direction at every level.

Approach: use TWO stacks. One stack holds the nodes of the CURRENT level to be printed in left-to-right order; the other collects the NEXT level's nodes so that, when it becomes the current stack, its nodes naturally come out in right-to-left order (since a stack reverses the order of insertion).

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;
 
public class SpiralOrderTraverser {
 
    public static List<Integer> traverseInSpiralOrder(TreeNode rootNode) {
        List<Integer> resultList = new ArrayList<>();
        if (rootNode == null) {
            return resultList;
        }
 
        Deque<TreeNode> currentLevelStack = new ArrayDeque<>();
        Deque<TreeNode> nextLevelStack = new ArrayDeque<>();
        currentLevelStack.push(rootNode);
        boolean isLeftToRightDirection = true;
 
        while (!currentLevelStack.isEmpty()) {
            TreeNode currentNode = currentLevelStack.pop();
            resultList.add(currentNode.nodeValue);
 
            if (isLeftToRightDirection) {
                // push left child before right child, so popping later
                // (in the NEXT level's stack) processes right-to-left
                if (currentNode.leftChild != null) nextLevelStack.push(currentNode.leftChild);
                if (currentNode.rightChild != null) nextLevelStack.push(currentNode.rightChild);
            } else {
                // push right child before left child, reversing the order
                // for the FOLLOWING level
                if (currentNode.rightChild != null) nextLevelStack.push(currentNode.rightChild);
                if (currentNode.leftChild != null) nextLevelStack.push(currentNode.leftChild);
            }
 
            if (currentLevelStack.isEmpty()) {
                // this level is fully processed -- swap in the next level's stack
                Deque<TreeNode> temporaryStack = currentLevelStack;
                currentLevelStack = nextLevelStack;
                nextLevelStack = temporaryStack;
                isLeftToRightDirection = !isLeftToRightDirection; // flip direction
            }
        }
        return resultList;
    }
 
    public static void main(String[] arguments) {
        TreeNode rootNode = new TreeNode(1);
        rootNode.leftChild = new TreeNode(2);
        rootNode.rightChild = new TreeNode(3);
        rootNode.leftChild.leftChild = new TreeNode(4);
        rootNode.leftChild.rightChild = new TreeNode(5);
        rootNode.rightChild.leftChild = new TreeNode(6);
        rootNode.rightChild.rightChild = new TreeNode(7);
 
        System.out.println(traverseInSpiralOrder(rootNode));
        // [1, 3, 2, 4, 5, 6, 7]
    }
}

Complexity: O(n) time, O(w) extra space, where w is the tree's maximum width (the largest number of nodes at any single level).

Q3. Binary tree zigzag traversal. (LeetCode.)
LeetCode: Binary Tree Zigzag Level Order Traversal ↗

Problem statement: This is the same underlying problem as spiral order traversal above, but LeetCode's specific version asks for the result GROUPED BY LEVEL (a List of Lists), rather than a single flat list.

import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;
 
public class ZigzagLevelOrderTraverser {
 
    public static List<List<Integer>> traverseZigzagByLevel(TreeNode rootNode) {
        List<List<Integer>> resultByLevel = new ArrayList<>();
        if (rootNode == null) {
            return resultByLevel;
        }
 
        Queue<TreeNode> nodesToVisit = new LinkedList<>();
        nodesToVisit.offer(rootNode);
        boolean isLeftToRightDirection = true;
 
        while (!nodesToVisit.isEmpty()) {
            int nodesAtThisLevel = nodesToVisit.size();
            List<Integer> currentLevelValues = new ArrayList<>();
 
            for (int count = 0; count < nodesAtThisLevel; count++) {
                TreeNode currentNode = nodesToVisit.poll();
 
                // add to the front or back of the list, depending on direction --
                // this produces the zigzag effect without needing a separate reversal step
                if (isLeftToRightDirection) {
                    currentLevelValues.add(currentNode.nodeValue);
                } else {
                    currentLevelValues.add(0, currentNode.nodeValue);
                }
 
                if (currentNode.leftChild != null) nodesToVisit.offer(currentNode.leftChild);
                if (currentNode.rightChild != null) nodesToVisit.offer(currentNode.rightChild);
            }
            resultByLevel.add(currentLevelValues);
            isLeftToRightDirection = !isLeftToRightDirection;
        }
        return resultByLevel;
    }
 
    public static void main(String[] arguments) {
        TreeNode rootNode = new TreeNode(3);
        rootNode.leftChild = new TreeNode(9);
        rootNode.rightChild = new TreeNode(20);
        rootNode.rightChild.leftChild = new TreeNode(15);
        rootNode.rightChild.rightChild = new TreeNode(7);
 
        System.out.println(traverseZigzagByLevel(rootNode));
        // [[3], [20, 9], [15, 7]]
    }
}

Complexity: O(n) time, O(w) extra space, where w is the tree's maximum width.

Binary Search Trees: Construction & Modification

Q4. Explain how a binary search is done, and how a Binary Search Tree (BST) works.
LeetCode: Related: Binary Search ↗

Problem statement: This is a conceptual question. A Binary Search Tree maintains the ordering invariant that, for every node, every value in its LEFT subtree is SMALLER than the node's own value, and every value in its RIGHT subtree is LARGER. This invariant is what lets a search proceed exactly like binary search on a sorted array: at each node, compare the target value to the current node's value, and move LEFT if the target is smaller, or RIGHT if the target is larger, discarding the other half of the tree at each step.

public class BinarySearchTreeSearcher {
 
    public static boolean containsValue(TreeNode currentNode, int targetValue) {
        if (currentNode == null) {
            return false; // reached a leaf's empty child -- value not found
        }
        if (targetValue == currentNode.nodeValue) {
            return true;
        } else if (targetValue < currentNode.nodeValue) {
            return containsValue(currentNode.leftChild, targetValue);  // search the left subtree
        } else {
            return containsValue(currentNode.rightChild, targetValue); // search the right subtree
        }
    }
}

Complexity: O(h) time, where h is the tree's height -- O(log n) for a balanced tree, but O(n) in the worst case for a completely unbalanced ("degenerate," essentially linked-list-shaped) tree.

Q5. Implement a Binary Search Tree, including insertion. (Asked multiple times in the original list.)
LeetCode: Insert Into A Binary Search Tree ↗

Problem statement: Implement a Binary Search Tree class supporting insertion of new values, maintaining the BST ordering invariant described above. Example: after inserting 5, 3, 7, 1, 4 (in that order), the tree should have 5 at the root, with 3 and 7 as its children, and 1 and 4 as children of 3.

public class BinarySearchTree {
 
    private TreeNode rootNode;
 
    public void insertValue(int newValue) {
        rootNode = insertValueRecursively(rootNode, newValue);
    }
 
    // Recursively finds the correct empty position for newValue, and returns
    // the (possibly newly-created) subtree rooted at currentNode
    private TreeNode insertValueRecursively(TreeNode currentNode, int newValue) {
        if (currentNode == null) {
            return new TreeNode(newValue); // found the correct empty spot -- create the new node here
        }
 
        if (newValue < currentNode.nodeValue) {
            currentNode.leftChild = insertValueRecursively(currentNode.leftChild, newValue);
        } else if (newValue > currentNode.nodeValue) {
            currentNode.rightChild = insertValueRecursively(currentNode.rightChild, newValue);
        }
        // if newValue already exists in the tree, do nothing (no duplicates)
 
        return currentNode;
    }
 
    public TreeNode getRootNode() {
        return rootNode;
    }
 
    public static void main(String[] arguments) {
        BinarySearchTree myTree = new BinarySearchTree();
        int[] valuesToInsert = {5, 3, 7, 1, 4};
        for (int currentValue : valuesToInsert) {
            myTree.insertValue(currentValue);
        }
        // resulting tree:      5
        //                    /   \
        //                   3     7
        //                  / \
        //                 1   4
    }
}

Complexity: O(h) time per insertion, where h is the tree's current height.

Q6. Delete a node from a Binary Search Tree.
LeetCode: Delete Node In A Bst ↗

Problem statement: Given the root of a BST and a value to delete, remove the node with that value while PRESERVING the BST ordering invariant for all remaining nodes. This has three distinct cases: the node has no children (simply remove it), the node has exactly one child (replace it with that child), and the node has two children (the tricky case).

Approach for the two-children case: replace the node's value with its IN-ORDER SUCCESSOR (the smallest value in its right subtree -- found by going right once, then left as far as possible), then recursively delete that successor from the right subtree (where it is now guaranteed to have at most one child, since it was the smallest value in that subtree).

public class BinarySearchTreeDeleter {
 
    public static TreeNode deleteValue(TreeNode currentNode, int targetValue) {
        if (currentNode == null) {
            return null; // value not found -- nothing to delete
        }
 
        if (targetValue < currentNode.nodeValue) {
            currentNode.leftChild = deleteValue(currentNode.leftChild, targetValue);
        } else if (targetValue > currentNode.nodeValue) {
            currentNode.rightChild = deleteValue(currentNode.rightChild, targetValue);
        } else {
            // found the node to delete -- handle its three possible shapes
 
            if (currentNode.leftChild == null) {
                return currentNode.rightChild; // no left child (0 or 1 children overall)
            } else if (currentNode.rightChild == null) {
                return currentNode.leftChild;  // no right child (exactly 1 child)
            }
 
            // two children: find the in-order successor (smallest value in
            // the right subtree), copy its value here, then delete IT instead
            TreeNode inOrderSuccessor = findMinimumValueNode(currentNode.rightChild);
            currentNode.nodeValue = inOrderSuccessor.nodeValue;
            currentNode.rightChild = deleteValue(currentNode.rightChild, inOrderSuccessor.nodeValue);
        }
        return currentNode;
    }
 
    private static TreeNode findMinimumValueNode(TreeNode currentNode) {
        while (currentNode.leftChild != null) {
            currentNode = currentNode.leftChild;
        }
        return currentNode;
    }
}

Complexity: O(h) time, where h is the tree's height.

Q7. Create a Binary Search Tree from a sorted array.
LeetCode: Convert Sorted Array To Binary Search Tree ↗

Problem statement: Given an array already sorted in ascending order, construct a HEIGHT-BALANCED Binary Search Tree containing those values. Example: buildBalancedBstFromSortedArray({1, 2, 3, 4, 5, 6, 7}) should produce a balanced tree with 4 at the root.

Approach: always pick the MIDDLE element of the current array range as the subtree's root -- this naturally keeps the left and right subtrees as close to equal in size as possible at every level, guaranteeing a balanced result.

public class SortedArrayToBstBuilder {
 
    public static TreeNode buildBalancedBstFromSortedArray(int[] sortedArray) {
        return buildFromRange(sortedArray, 0, sortedArray.length - 1);
    }
 
    private static TreeNode buildFromRange(int[] sortedArray, int startIndex, int endIndex) {
        if (startIndex > endIndex) {
            return null; // empty range -- no subtree here
        }
 
        int middleIndex = startIndex + (endIndex - startIndex) / 2;
        TreeNode currentRootNode = new TreeNode(sortedArray[middleIndex]);
 
        // recursively build the left half (elements before the middle) and
        // the right half (elements after the middle) as balanced subtrees
        currentRootNode.leftChild = buildFromRange(sortedArray, startIndex, middleIndex - 1);
        currentRootNode.rightChild = buildFromRange(sortedArray, middleIndex + 1, endIndex);
 
        return currentRootNode;
    }
 
    public static void main(String[] arguments) {
        int[] sortedArray = {1, 2, 3, 4, 5, 6, 7};
        TreeNode rootNode = buildBalancedBstFromSortedArray(sortedArray);
        System.out.println(rootNode.nodeValue); // 4
    }
}

Complexity: O(n) time (each element becomes exactly one node), O(log n) extra space for the recursive call stack (since the resulting tree is balanced by construction).

Q8. Build a tree using two arrays: one containing the tree in traversal (pre-order) order, and the other in-order.
LeetCode: Construct Binary Tree From Preorder And Inorder Traversal ↗

Problem statement: Given a pre-order traversal array and an in-order traversal array of the SAME binary tree, reconstruct the original tree. Example: given preOrderValues = {3, 9, 20, 15, 7} and inOrderValues = {9, 3, 15, 20, 7}, reconstruct the original tree.

Approach: the FIRST value in the pre-order array is always the ROOT of the (sub)tree. Locate that same value within the in-order array -- everything to its LEFT in the in-order array belongs to the LEFT subtree, and everything to its RIGHT belongs to the RIGHT subtree. Apply this recursively.

import java.util.HashMap;
import java.util.Map;
 
public class TreeBuilderFromTraversals {
 
    private static int preOrderIndex;
    private static Map<Integer, Integer> valueToInOrderIndex;
 
    public static TreeNode buildTreeFromTraversals(int[] preOrderValues, int[] inOrderValues) {
        preOrderIndex = 0;
        valueToInOrderIndex = new HashMap<>();
 
        // precompute each value's position in the in-order array, for O(1) lookup
        for (int index = 0; index < inOrderValues.length; index++) {
            valueToInOrderIndex.put(inOrderValues[index], index);
        }
 
        return buildSubtree(preOrderValues, 0, inOrderValues.length - 1);
    }
 
    // Builds the subtree corresponding to the in-order range [inOrderStart, inOrderEnd]
    private static TreeNode buildSubtree(int[] preOrderValues, int inOrderStart, int inOrderEnd) {
        if (inOrderStart > inOrderEnd) {
            return null;
        }
 
        // the NEXT value in pre-order is always the root of the current subtree
        int currentRootValue = preOrderValues[preOrderIndex];
        preOrderIndex++;
        TreeNode currentRootNode = new TreeNode(currentRootValue);
 
        int rootPositionInOrder = valueToInOrderIndex.get(currentRootValue);
 
        // everything to the LEFT of the root's position (in-order) is the left subtree;
        // build it FIRST, since pre-order visits left subtree entries before right ones
        currentRootNode.leftChild = buildSubtree(preOrderValues, inOrderStart, rootPositionInOrder - 1);
        currentRootNode.rightChild = buildSubtree(preOrderValues, rootPositionInOrder + 1, inOrderEnd);
 
        return currentRootNode;
    }
 
    public static void main(String[] arguments) {
        int[] preOrderValues = {3, 9, 20, 15, 7};
        int[] inOrderValues = {9, 3, 15, 20, 7};
 
        TreeNode rootNode = buildTreeFromTraversals(preOrderValues, inOrderValues);
        System.out.println(rootNode.nodeValue); // 3 (the root)
    }
}

Complexity: O(n) time, using the precomputed HashMap to look up each value's in-order position in O(1) rather than searching linearly. O(n) extra space for the map and the recursive call stack.

Binary Search Tree Validation & Comparison

Q9. Validate that a tree is a proper Binary Search Tree. (Asked three times in the original list.)
LeetCode: Validate Binary Search Tree ↗

Problem statement: Given the root of a binary tree, determine whether it satisfies the Binary Search Tree property: for EVERY node, ALL values in its left subtree must be smaller than the node's value, and ALL values in its right subtree must be larger -- not just checking the node's IMMEDIATE children, but every descendant.

Note: A common mistake: checking only that leftChild.nodeValue < currentNode.nodeValue < rightChild.nodeValue at every node is NOT sufficient. This local check can pass even for an INVALID BST -- for example, a node with value 10 whose right child has value 15, but that right child's OWN left child has value 5, would incorrectly pass a purely local check, even though 5 violates the BST property relative to the ORIGINAL node with value 10 (5 is in the right subtree of 10, but is smaller than 10).
public class BinarySearchTreeValidator {
 
    public static boolean isValidBst(TreeNode rootNode) {
        // pass down an allowed [lowerBound, upperBound) range that narrows
        // as we descend, rather than only checking IMMEDIATE children
        return isValidBstInRange(rootNode, Long.MIN_VALUE, Long.MAX_VALUE);
    }
 
    private static boolean isValidBstInRange(TreeNode currentNode, long lowerBound, long upperBound) {
        if (currentNode == null) {
            return true; // an empty subtree is trivially valid
        }
 
        if (currentNode.nodeValue <= lowerBound || currentNode.nodeValue >= upperBound) {
            return false; // violates the allowed range established by an ANCESTOR node
        }
 
        // the left subtree's values must all be less than currentNode's value;
        // the right subtree's values must all be greater
        return isValidBstInRange(currentNode.leftChild, lowerBound, currentNode.nodeValue)
            && isValidBstInRange(currentNode.rightChild, currentNode.nodeValue, upperBound);
    }
 
    public static void main(String[] arguments) {
        TreeNode validTree = new TreeNode(5);
        validTree.leftChild = new TreeNode(3);
        validTree.rightChild = new TreeNode(8);
        System.out.println(isValidBst(validTree)); // true
 
        TreeNode invalidTree = new TreeNode(10);
        invalidTree.rightChild = new TreeNode(15);
        invalidTree.rightChild.leftChild = new TreeNode(5); // 5 violates BST property relative to root (10)
        System.out.println(isValidBst(invalidTree)); // false
    }
}
Note: An equally valid alternative approach: perform an IN-ORDER traversal and check that the resulting sequence of values is STRICTLY INCREASING -- since a valid BST's in-order traversal always produces sorted output, and conversely, any tree whose in-order traversal is sorted must be a valid BST. Both approaches run in O(n) time.

Complexity: O(n) time (every node is visited once), O(h) extra space for the recursive call stack.

Q10. How do you compare two trees (to determine whether they are identical)?
LeetCode: Same Tree ↗

Problem statement: Given the roots of two binary trees, determine whether they are structurally IDENTICAL, with the SAME values at every corresponding position. Example: two trees with the same shape and the same values at every node should be considered equal; if either the shape or any value differs, they are not.

public class BinaryTreeComparator {
 
    public static boolean areTreesIdentical(TreeNode firstRoot, TreeNode secondRoot) {
        if (firstRoot == null && secondRoot == null) {
            return true; // both empty -- identical
        }
        if (firstRoot == null || secondRoot == null) {
            return false; // exactly one is empty -- not identical
        }
        if (firstRoot.nodeValue != secondRoot.nodeValue) {
            return false; // values differ at this position
        }
 
        // both current nodes match -- recursively verify BOTH subtrees match too
        return areTreesIdentical(firstRoot.leftChild, secondRoot.leftChild)
            && areTreesIdentical(firstRoot.rightChild, secondRoot.rightChild);
    }
 
    public static void main(String[] arguments) {
        TreeNode firstTree = new TreeNode(1);
        firstTree.leftChild = new TreeNode(2);
        firstTree.rightChild = new TreeNode(3);
 
        TreeNode secondTree = new TreeNode(1);
        secondTree.leftChild = new TreeNode(2);
        secondTree.rightChild = new TreeNode(3);
 
        System.out.println(areTreesIdentical(firstTree, secondTree)); // true
    }
}

Complexity: O(min(n, m)) time, where n and m are the two trees' sizes (the comparison stops as soon as any mismatch is found). O(h) extra space for the recursive call stack.

Tree Paths & Value Transformation

Q11. Find the maximum unique values in a tree along a single path.

Problem statement: Given a binary tree, find the length (or count of DISTINCT values) along the path from the root to some leaf that contains the MOST unique values. This is interpreted here as: find the root-to-leaf path containing the greatest number of distinct values.

import java.util.HashSet;
import java.util.Set;
 
public class MaximumUniqueValuePathFinder {
 
    private static int maximumUniqueCountFound = 0;
 
    public static int findMaximumUniqueValuesOnPath(TreeNode rootNode) {
        maximumUniqueCountFound = 0;
        exploreEveryPath(rootNode, new HashSet<>());
        return maximumUniqueCountFound;
    }
 
    private static void exploreEveryPath(TreeNode currentNode, Set<Integer> valuesOnCurrentPath) {
        if (currentNode == null) {
            return;
        }
 
        boolean wasNewValue = valuesOnCurrentPath.add(currentNode.nodeValue);
 
        if (currentNode.leftChild == null && currentNode.rightChild == null) {
            // reached a leaf -- this path is complete; check if it's the best so far
            maximumUniqueCountFound = Math.max(maximumUniqueCountFound, valuesOnCurrentPath.size());
        } else {
            exploreEveryPath(currentNode.leftChild, valuesOnCurrentPath);
            exploreEveryPath(currentNode.rightChild, valuesOnCurrentPath);
        }
 
        // backtrack: remove this node's value before returning to the parent,
        // so SIBLING paths don't incorrectly see it as part of THEIR path
        if (wasNewValue) {
            valuesOnCurrentPath.remove(currentNode.nodeValue);
        }
    }
 
    public static void main(String[] arguments) {
        TreeNode rootNode = new TreeNode(1);
        rootNode.leftChild = new TreeNode(2);
        rootNode.rightChild = new TreeNode(2);
        rootNode.leftChild.leftChild = new TreeNode(3);
 
        System.out.println(findMaximumUniqueValuesOnPath(rootNode)); // 3
    }
}

Complexity: O(n x h) time in the worst case (each of the n nodes may be visited once per path, and there can be up to h paths of length h). O(h) extra space for the current path's value set and the recursive call stack.

Q12. Replace every node in a BST with the sum of every node greater than or equal to it.
LeetCode: Convert Bst To Greater Tree ↗

Problem statement: Given a Binary Search Tree, transform it so that every node's value is replaced with the SUM of its original value plus every value GREATER than it in the original tree. This is the classic "Convert BST to Greater Tree" problem. Example: for a BST containing {2, 5, 13}, the value 13 becomes 13 (nothing greater), 5 becomes 5+13=18, and 2 becomes 2+5+13=20.

Approach: perform a REVERSE in-order traversal (right subtree, then node, then left subtree) -- this visits nodes in DESCENDING order, letting a running sum accumulate exactly the total of every value seen so far (which is always greater than or equal to the current node) as the traversal proceeds.

public class BstToGreaterSumTreeConverter {
 
    private static int runningSumOfGreaterValues = 0;
 
    public static TreeNode convertToGreaterSumTree(TreeNode rootNode) {
        runningSumOfGreaterValues = 0;
        traverseInReverseOrder(rootNode);
        return rootNode;
    }
 
    // Visits nodes from LARGEST to SMALLEST value (right, node, left) --
    // the opposite of a standard in-order traversal
    private static void traverseInReverseOrder(TreeNode currentNode) {
        if (currentNode == null) {
            return;
        }
 
        traverseInReverseOrder(currentNode.rightChild); // visit larger values first
 
        runningSumOfGreaterValues += currentNode.nodeValue;
        currentNode.nodeValue = runningSumOfGreaterValues; // replace with the accumulated sum
 
        traverseInReverseOrder(currentNode.leftChild);   // then visit smaller values
    }
 
    public static void main(String[] arguments) {
        TreeNode rootNode = new TreeNode(5);
        rootNode.leftChild = new TreeNode(2);
        rootNode.rightChild = new TreeNode(13);
 
        convertToGreaterSumTree(rootNode);
        System.out.println(rootNode.nodeValue);            // 18 (5 + 13)
        System.out.println(rootNode.leftChild.nodeValue);   // 20 (2 + 5 + 13)
        System.out.println(rootNode.rightChild.nodeValue);  // 13 (nothing greater)
    }
}

Complexity: O(n) time (every node is visited exactly once), O(h) extra space for the recursive call stack.

Graph Search: DFS, BFS & Number of Islands

Q13. Graph searches and special cases of graph exploration (DFS). (Asked multiple times in the original list.)

Problem statement: Implement both Depth-First Search (DFS) and Breadth-First Search (BFS) on a graph represented as an adjacency list, and discuss when each is the right choice.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.HashSet;
import java.util.LinkedList;
import java.util.List;
import java.util.Map;
import java.util.Queue;
import java.util.Set;
 
public class GraphSearcher {
 
    // Depth-First Search: dives as deep as possible down one path before
    // backtracking. Implemented ITERATIVELY here using an explicit stack
    // (an equally valid, and often simpler, RECURSIVE version also exists).
    public static List<String> searchDepthFirst(Map<String, List<String>> adjacencyList, String startingNode) {
        List<String> visitOrder = new ArrayList<>();
        Set<String> visitedNodes = new HashSet<>();
        Deque<String> nodesToExplore = new ArrayDeque<>();
        nodesToExplore.push(startingNode);
 
        while (!nodesToExplore.isEmpty()) {
            String currentNode = nodesToExplore.pop();
            if (visitedNodes.contains(currentNode)) {
                continue; // already processed -- skip
            }
            visitedNodes.add(currentNode);
            visitOrder.add(currentNode);
 
            for (String neighborNode : adjacencyList.getOrDefault(currentNode, List.of())) {
                if (!visitedNodes.contains(neighborNode)) {
                    nodesToExplore.push(neighborNode);
                }
            }
        }
        return visitOrder;
    }
 
    // Breadth-First Search: explores all neighbors at the current distance
    // before moving further out -- guarantees the SHORTEST path is found first
    public static List<String> searchBreadthFirst(Map<String, List<String>> adjacencyList, String startingNode) {
        List<String> visitOrder = new ArrayList<>();
        Set<String> visitedNodes = new HashSet<>();
        Queue<String> nodesToExplore = new LinkedList<>();
        nodesToExplore.offer(startingNode);
        visitedNodes.add(startingNode);
 
        while (!nodesToExplore.isEmpty()) {
            String currentNode = nodesToExplore.poll();
            visitOrder.add(currentNode);
 
            for (String neighborNode : adjacencyList.getOrDefault(currentNode, List.of())) {
                if (!visitedNodes.contains(neighborNode)) {
                    visitedNodes.add(neighborNode); // mark visited WHEN ENQUEUED, not when processed
                    nodesToExplore.offer(neighborNode);
                }
            }
        }
        return visitOrder;
    }
}

When to use each: use BFS whenever the problem asks for the SHORTEST path or minimum number of steps in an unweighted graph (BFS guarantees the first time any node is reached, it's via the shortest possible path). Use DFS when you need to explore an entire connected region (as in the Number of Islands problem below), detect cycles, or when the specific ORDER of exploration doesn't matter and a simpler, often more memory-efficient (especially with the recursive call-stack-based version) traversal is sufficient.

Complexity: O(V + E) time for both DFS and BFS, where V is the number of vertices and E is the number of edges -- every vertex and edge is examined a constant number of times. O(V) extra space for the visited set and the stack/queue.
